# 履歴書・職務経歴書・推薦書ジェネレーター（Google Apps Script 版）

Google スプレッドシートに入力 → メニュー操作だけで、**履歴書（JIS 様式ベース）**・**職務経歴書（コンサル・IT 業界向け標準構成）**・**推薦書（人材紹介の推薦状）** を Google ドキュメント／PDF で生成します。候補者ごとに「〇〇様」フォルダーを作り、既存の履歴書やメモなどの添付資料を AI で読み取って入力シートを埋められます。
社用 PC のように **Google Workspace しか使えない環境** で、私用 PC（Claude Code）と同じ品質の書類を出すためのツールです。

```
gas/resume-kit/
├─ src/               ソース（Apps Script）。10 ファイル、依存なし
├─ dist/resume-kit.gs 上記を 1 ファイルに連結したもの（社用 PC はこれを貼るだけ）
├─ test/run-tests.mjs 純粋ロジックの単体テスト
├─ test/e2e.mjs      GAS モック上でメニュー操作を通しで実行するテスト
├─ test/gas-mock.mjs 使用している GAS メソッドだけを再現したモック
├─ bundle.mjs         src → dist を作る
└─ appsscript.json    マニフェスト（タイムゾーン Asia/Tokyo, V8）
```

## 社用 PC への展開（Workspace のみ・所要 5 分）

1. Google ドライブで **新規スプレッドシート** を作る（名前は「履歴書_作成用」など）
2. メニュー **拡張機能 → Apps Script** を開く
3. 左の `コード.gs` の中身を全部消し、GitHub 上の [`dist/resume-kit.gs`](./dist/resume-kit.gs) を **Raw 表示 → 全選択 → コピー → 貼り付け**
4. 左の **プロジェクトの設定（歯車）→「appsscript.json」マニフェストを表示** にチェックし、`appsscript.json` の中身を [`appsscript.json`](./appsscript.json) で置き換える（タイムゾーンを東京にするため。省略しても動く）
5. 💾 保存 → スプレッドシートに戻って **再読み込み**（F5）
6. メニューに **「履歴書ツール」** が出るので **① 初期セットアップ（サンプル投入）** を実行  
   初回は Google の承認画面が出ます。「詳細 → （プロジェクト名）に移動」→ 許可
7. 各シートを自分の内容に書き換え → **② 入力チェック** → **③ 両方を生成**

git も Node も不要です。ブラウザで GitHub を開けない場合は、`dist/resume-kit.gs` をメールや Drive で社用アカウントに送って貼り付けてください。

### 更新のしかた
私用 PC で `src/` を直し `node gas/resume-kit/bundle.mjs` で `dist/` を作り直して push。社用 PC では手順 3 の貼り直しだけで更新できます（シートのデータは残ります）。
`clasp` が使える環境なら `.clasp.json.example` を `.clasp.json` にコピーしてスクリプト ID を入れ、`npx @google/clasp push` でも配布できます。

## 候補者ごとの運用（新規作成 → 添付 → 取り込み → 生成）

1. マスターのスプレッドシートで **⓪ 新規候補者を作成**。氏名と作成場所（任意のフォルダー）を聞かれ、次を作ります
   ```
   <選んだフォルダー>/
   └─ 山田 花子様/
      ├─ 山田 花子様_入力シート   ← マスターの複製（入力は空、設定・テンプレート・推薦者欄は引き継ぐ）
      └─ 添付資料/
   ```
   複製したシートを開くと、スクリプトの承認をもう一度求められます
2. 入力シートで **② 添付資料を追加**。ダイアログから PC のファイル／フォルダー（中身ごと）をアップロードするか、ドライブのファイル／フォルダーの URL を貼ります。「添付資料」シートに一覧が出ます
3. **② 添付資料から入力シートを作成（AI）**。「取り込む」にチェックした資料を読み取り、AI が各シートを埋めます
   - 「空欄だけ埋める」（推奨）: 入力済みの値や行は変えません
   - 「置き換える」: 読み取った内容でシートを置き換えます
   - 要確認事項と AI の返答原文は「取り込み結果」シートに残ります
4. **② 入力チェック** → **③ 3 点すべて生成**。「山田 花子様」フォルダーに `山田 花子様_履歴書` `…_職務経歴書` `…_推薦書` と各 PDF ができます

読み取れる資料:

| 形式 | 読み方 |
|---|---|
| Google ドキュメント / スプレッドシート / スライド | 本文をそのまま |
| Word / Excel / PowerPoint | 一時的に Google 形式へ変換して読み、一時ファイルはゴミ箱へ |
| PDF・画像 | AI に直接渡す（1 件 10MB・合計 18MB まで）。超えた分や Claude 非対応の画像形式は Drive の OCR（日本語）で文字にする |
| テキスト・CSV | そのまま（Shift_JIS も可） |

PC からのアップロードは 1 ファイル 15MB まで。大きいファイルはドライブに置いて URL で登録してください。

## 推薦書

「推薦書」シートに推薦先・推薦ポジション・推薦者・推薦ポイント（1 行 1 項目）・推薦文・人物像・転職理由・懸念点と見解・年収・入社可能時期を入れます。「面談メモ」は書類には出ず、AI 下書きにだけ使います。

- **④ 推薦書を AI で下書き**: 候補者情報と面談メモから推薦ポイント・推薦文・人物像・懸念点の下書きを「AI提案」シートに出します。チェックした行だけ反映されます
- 標準レイアウト: 宛先（御中）・推薦者 → 推薦書 → 候補者概要表 → 推薦理由 → 推薦文 → 経歴概要 → 人物像 → 転職理由 → 懸念点と見解 → 敬具
- 会社規定の推薦書がある場合は「設定」の `推薦書テンプレート` に URL を入れます。トークンは `{{推薦先企業}}` `{{推薦ポジション}}` `{{推薦ポイント}}` `{{推薦文}}` `{{人物像}}` `{{懸念点}}` `{{現職}}` `{{最終学歴}}` `{{希望年収}}` など（⑤ トークン一覧）

## シート構成

| シート | 用途 | 使う書類 |
|---|---|---|
| 基本情報 | 氏名・住所・連絡先・志望動機・本人希望・写真 | 履歴書 |
| 学歴 | 年 / 月 / 学校名 / 区分（入学・卒業…） | 両方 |
| 職歴 | 入退社年月・会社名・**雇用形態**・部門・会社概要 | 両方 |
| プロジェクト | 会社ごとの業務・プロジェクト詳細（概要／支援内容／成果） | 職務経歴書 |
| 経験・能力 | 見出し＋本文。本文が空なら **ミッション→目標数字→課題→工夫点→結果** から自動生成 | 職務経歴書 |
| 免許・資格 | 区分（免許・資格／語学／ツール・技術）、「履歴書に載せる」○ | 両方 |
| 実績 | 表彰／登壇 | 職務経歴書 |
| 文章 | 職務要約・自己PR | 職務経歴書 |
| 推薦書 | 推薦先・推薦者・推薦ポイント・推薦文・面談メモなど | 推薦書 |
| 添付資料 | 読み取る資料の一覧（「取り込む」チェック） | - |
| 設定 | 保存先・ファイル名パターン・テンプレート・フォント・PDF・AI | - |

## 入力チェックの主なルール（大手ファーム選考の「応募書類確認の留意点」準拠）

- 学歴・職歴は **西暦統一**（和暦を検出すると警告）
- **雇用形態は必須**。無記載＝正社員とみなされ、相違は内定取消の対象。履歴書では正社員以外を「〇〇として入社」と明記
- **学歴 1 年以上／職歴 1 ヶ月以上の空白** を検出（面接で理由を聞かれる）
- 在籍期間の重複、退社が入社より前、プロジェクト開始が入社より前
- プロジェクトの会社名が職歴と完全一致しているか
- 実績・経験に **数値** があるか（再現性 = 「どういう考え方で結果を出したか」）
- 職務要約 200〜400 字、自己PR 300〜600 字の目安
- 会社名・資格の正式名称、メールアドレスの印象、番地まで書いた住所

## 保存先とファイル名

- 生成時に **保存先フォルダ** を聞くダイアログが出ます（URL／ID／フォルダ名。存在しない名前ならマイドライブ直下に作成）。前回の選択を記憶し、空欄ならそれを使います。毎回聞かれたくない場合は「設定」の `出力フォルダ` に入れてください
- **ファイル名** は「設定」の `ファイル名パターン` で決まります。既定は `{氏名}様_{種別}` → `田中 太郎様_履歴書`。`{日付}` も使えます

## 会社規定の用紙（テンプレート）に流し込む

用紙が Google ドキュメント／スプレッドシート／Word／Excel なら、その用紙のまま仕上げられます（Word・Excel は Google 形式に変換したコピーを作ります。PDF だけの用紙は埋められないので原本を入手してください）。

1. 用紙の埋めたい場所に **トークン** を書く（メニュー ⑤「トークン一覧を表示」で全一覧）
   - 単一値: `{{氏名}}` `{{ふりがな}}` `{{生年月日}}` `{{年齢}}` `{{現住所}}` `{{メール}}` `{{志望動機}}` `{{職務要約}}` `{{自己PR}}` `{{職務経歴詳細}}` など
   - 会社枠: `{{会社_見出し}}` `{{会社_事業内容}}` `{{会社_担当業務}}` `{{会社_実績}}` などを置いた表（スプレッドシートは行のまとまり）を、会社の数だけ複製します
   - 行リスト: 表の 1 行に `{{学歴職歴_年}}` `{{学歴職歴_月}}` `{{学歴職歴_内容}}` を置くと、行数分に展開（ドキュメントは行を複製、スプレッドシートは下方向に書き込み）。`学歴` `職歴` `資格` `所属企業` も同様
   - 罫線の行数が決まった用紙は、トークン行を罫線の行数だけ並べておくと上から順に埋めます。ドキュメントは件数が多ければ行を追加し、スプレッドシートは欄の外に書かずに「〇行足りません」と知らせます
   - 見開きの用紙（左の表の続きが右の表）は、左の列の表から順に埋めます
   - 「入学」「卒業」「入社」「退職」を別の欄に書く用紙は `{{学歴職歴_名称}}` と `{{学歴職歴_区分}}` を使います（`内容` は「学校名 卒業」の 1 文）
   - `{{写真}}`（ドキュメントのみ）: 写真ファイル ID の画像を挿入
2. トークンが 1 つも無い用紙は ⑤「用紙にトークンを自動挿入」で、「ふりがな」「氏名」「学歴・職歴」などのラベルを手掛かりに右隣／次の行へトークンを入れたコピーを作ります。「ふりがな」は直下の欄（氏名／現住所／連絡先）で振り分け、連絡先側の 2 つ目の「電話」などは入れません。表の外の「■職務要約」のような見出しにも対応します。開いて位置を確認・修正してください
3. ⑤「テンプレートを診断」で認識トークン／不明トークン／不足を確認
4. 「設定」の `履歴書テンプレート` / `職務経歴書テンプレート` に用紙の URL を入れて ③ 生成

残ったトークンは生成時に空文字に置換されます。

### 自動挿入が対応している用紙の形

| 用紙の書き方 | 自動で入るトークン |
|---|---|
| `20xx年xx月xx日現在` / `氏名　○○ ○○` のような穴埋め表記（ヘッダー・フッター含む） | `{{作成日}}現在` / `氏名　{{氏名}}` |
| 表のラベル（「ふりがな」「氏名」「学歴・職歴」…） | 右隣のセル、行リストは次の行 |
| `氏名：` `年齢：` `住まい：` のような「ラベル：」の段落 | 同じ行の右（`年齢：{{年齢}}歳`） |
| `■職務要約` `■資格` `■スキル・経験` `■自己PR` のような見出し、`退職理由：` `推薦コメント：` のような文章欄 | 次の空行 |
| 職務経歴の枠（「事業内容」「担当業務」「実績」を含む表） | `{{会社_見出し}}` `事業内容：{{会社_事業内容|不明}}` `{{会社_担当業務}}` `{{会社_実績}}` など。生成時に会社の数だけ表を複製 |

`{{名前|既定値}}` と書くと、値が空のとき既定値が出ます（例: `上場：{{会社_上場|未上場}}`）。用紙にもともと書かれていた「不明」「未上場」は自動挿入でこの既定値になります。

### テンプレート台帳と選択（1 つのスプレッドシートに複数のテンプレート）

1. ⑤「テンプレートを登録」に用紙の URL を入れます。スプレッドシートはシート（タブ）ごとに 1 件ずつ「テンプレート」シートに登録され、種別（履歴書／職務経歴書／推薦書）はシート名から推定します
2. 生成時、同じ種別が 2 件以上あれば番号で選びます（0 = 標準レイアウト、空欄 = 前回の選択か ○ を付けた既定）。1 件だけなら聞かずに使います
3. 選んだシートだけを残したコピーに流し込みます。スプレッドシートの会社枠（`{{会社_...}}` を含む行のまとまり）は会社の数だけ行を挿入して複製し、下の内容は押し下げます

台帳に無い種別は、従来どおり「設定」シートの `〇〇テンプレート` を使います。

## AI 分析・添削（Gemini / Claude）

- **④ 分析して提案を作る**: 社内ルールで分析し、「AI提案」シートに **総評** と **項目ごとの修正提案**（番地・現在の値・提案文・理由・優先度）を書き出します。採用する行の「反映」にチェックを付けて **「チェックした提案を反映」** を実行すると、該当セルに書き戻します。AI が勝手に事実を書き換えない設計です
- プロバイダは「設定」の `AIプロバイダ`（gemini / claude）。キーは ④「APIキーを設定」でユーザープロパティに保存（共有者に見えない）。Gemini は Google AI Studio のキー、Claude は Anthropic のキー
- **④ 添削プロンプトだけ作る**: 外部 API が使えない環境向け。番地付きの入力内容とルールをまとめた文を「AI添削」シートに出すので、Workspace の Gemini に貼れば添削できます

## 会社版（社名入り）

- 「設定」の `会社フッター`（社名・許可番号など、1 行ずつ）と `会社ロゴファイルID` を入れると、標準レイアウトの職務経歴書・推薦書のフッターに入ります。履歴書は本人の書類なので入れません
- 会社ごとの既定値（フッター・推薦者会社・メニュー名）を焼き込んだ貼り付け用ファイルを作れます:
  ```bash
  cp -r gas/resume-kit/companies/_example gas/resume-kit/companies/<会社名>   # 05_Company.js を書き換える
  node gas/resume-kit/bundle.mjs --company gas/resume-kit/companies/<会社名>   # → dist/resume-kit-<会社名>.gs
  ```
- `companies/` の実データと `dist/resume-kit-*.gs` は `.gitignore` で除外しています。公開リポジトリに社名入りのファイルを載せないためです。会社版は非公開の場所で管理してください
- スプレッドシートの用紙の PDF は、使用範囲の縦横比で向きを決め、A4・幅に合わせて書き出します

## 個人情報の扱い（重要）

- **Gemini API の無料枠は、送った内容が Google のサービス改善に使われる規約です。候補者の個人情報を扱うなら、課金を有効にした（有料枠の）API キーを使ってください。** 外部 API を使わない運用なら「添削プロンプトだけ作る」で Workspace 内の Gemini に貼る方法が残ります
- 推薦書は候補者の情報を第三者（推薦先企業）に渡す書類です。提出前に本人の同意を取る運用にしてください

- このリポジトリは **公開リポジトリ**。実データ（氏名・住所・電話）は **絶対にコミットしない**。サンプルは架空の「田中 太郎」のみ
- 入力したスプレッドシートと生成ドキュメントは各自の Google ドライブに残る。共有設定を「制限付き」にする
- 生成物は Drive の「履歴書_出力」フォルダ（または設定で指定したフォルダ）に保存。古い PDF は同名なら上書き

## 制約

- Apps Script の 1 回の実行は 6 分までです。取り込みで資料が多い、または大きい場合は「取り込む」のチェックを減らして分けて実行してください
- 取り込みは速さを優先して `Gemini抽出モデル`（既定 gemini-2.5-flash）を使います。通信がタイムアウトする場合も資料を減らしてください

## 開発（私用 PC）

```bash
npm run test:gas    # 単体テスト + GAS モック上の通しテスト
npm run build:gas   # dist/resume-kit.gs を再生成（コミットに含める）
```

モックは「実行時に落ちないこと」と「生成物の中身」を検証します。フォント・罫線・余白などの見た目は検証できないので、レイアウトを変えたら実際のスプレッドシートで「③ 両方を生成」して目視確認してください。

標準レイアウトはセル結合を使いません（DocumentApp はセル結合を正式に扱えないため）。履歴書の氏名欄は列構成ごとの表を縦に積み、職務経歴書は会社ごとに 2 列表 1 つで組んでいます。
